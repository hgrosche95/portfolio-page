Begann als reine "Claude Code Skill" — ein Ordner mit Anweisungen (`SKILL.md`), den Claude automatisch lädt, sobald jemand eine Stellenanzeige teilt: Lebenslauf und Anzeige einsammeln, 3–5 Anforderungen ehrlich gegen die eigene Erfahrung abgleichen (Lücken benennen statt erfinden), ein Anschreiben entwerfen, mit Rückmeldung verfeinern, am Ende einen Bewerbungsordner samt PDF anlegen. Das läuft komplett in der Klartext-Anleitung, keine Zeile Code für die inhaltlichen Entscheidungen.

**Warum der Ausbau zum Dienst:** Als Teil von [life-ops-platform](/projects/life-ops-platform) sollte dieselbe Fähigkeit auch außerhalb einer einzelnen Claude-Code-Session nutzbar sein — von unterwegs per Claude Desktop, und automatisiert durch n8n (z. B. eine Jobbörse beobachten und selbstständig gegen den eigenen Lebenslauf abgleichen). Das bedeutet: ein echtes Backend, ein MCP-Server für Claude, eine REST-API für n8n. Die drei ursprünglichen Python-Skripte (Lebenslauf/Anschreiben als PDF, Bewerbungsordner anlegen) blieben dabei unverändert — sie werden jetzt vom NestJS-Backend aus aufgerufen statt direkt von Claude, machen aber inhaltlich dasselbe.

**Technisch interessant:** `match_job_posting` und `draft_cover_letter` laufen jetzt serverseitig gegen ein LLM (Groq als kostenloser Standard, Anthropic als Fallback) statt in Claudes eigener Session — mit derselben Leitplanke wie im ursprünglichen Skill, nur diesmal als Prompt-Regel statt als Markdown-Anweisung: keine erfundenen Erfahrungen oder Kennzahlen. Live beim Testen gezeigt, dass das nicht zuverlässig genug ist — das Modell erfand trotzdem gelegentlich Zahlen. Dafür gibt es einen Validierungs-Loop nach dem Muster des `encounter_agent`-Patterns aus `agentic-rogue-like`: generieren, deterministisch prüfen, bei Verstoß mit dem konkreten Fehler im Prompt erneut versuchen (gedeckelt auf 3 Versuche). Ehrlicher Stand: Der Loop prüft bisher Wortzahl und Floskeln, erfundene Kennzahlen fängt er noch nicht ab. Der nächste Schritt ist ein Grounding-Check, bei dem jede Zahl im Anschreiben auch im Lebenslauf stehen muss. Jeder Versuch bekommt einen eigenen verschachtelten Langfuse-Span — der Loop ist damit vollständig nachvollziehbar, nicht nur eine Black Box, die irgendwann einen Text ausspuckt.

**Deployment:** Läuft als Container App in Azure, mit Python direkt im selben Container wie das NestJS-Backend (`node:20-slim` + `apt install python3`), weil die PDF-Skripte weiterhin echte Python-Prozesse sind, kein Node-Äquivalent. Details zur geteilten Infrastruktur (RAG, Langfuse) und ein paar echte Stolpersteine beim Azure-Deployment stehen bei [life-ops-platform](/projects/life-ops-platform).
